## What was built

### Delegated passes that only narrow (#58, HM-29, ADR 0025)

- `hall_monitor/delegation.py`: code issues a lead agent's grant for one case; each handoff makes
  a child grant inside both the parent grant and the helper's own manifest.
- New manifest field `may_delegate_to`. An empty list is left out of the digest, so existing
  approvals still match.
- Over-asking is refused and logged, never trimmed. The confused-deputy case is tested: a helper
  whose manifest allows health data can't get it from a parent that wasn't given it.
- No loops, at most two handoffs, allotments only shrink. The whole chain is checked on every use,
  so stopping the lead stops its helpers. The case's grant book is the authority; closing it ends
  every grant.
- The tool gateway serves a delegating or delegated agent only under a grant its case's book
  issued. New audit events `delegation_granted` and `delegation_refused`.
- Design in `docs/complaint-crew-design.md`. No agent uses grants yet.

### Red-team arena (#59, HM-30, ADR 0026)

- `python -m hall_monitor.redteam` (`--publish` writes results; `--live` refuses).
- Attacker: 18 synthetic seeds in `data/synthetic/redteam/complaints.yaml` in four families
  (injection, fake urgency, drafts carrying a link/phone/email/promise, must-route complaints
  played down). Each round applies the next mutation: plain, HTML entities, full-width,
  zero-width, entities encoded twice, look-alike letters, spelled out.
- Defender: the desk's real pipeline with the triage agent replaced by a stand-in that does
  whatever the attack asks, i.e. a fully hijacked model. Tracing is off for the run.
- Judge: code, scoring against what each seed says was planted and a human `must_route` label.
  Breaches are harm (`must_route_missed`, `draft_kept_with_delivery`, `text_in_log`), a failed
  defence layer (`injection_unflagged`), or an accepted trade-off (`urgency_inflated`).
- Scripted `agent_call` entries now carry `scripted: true`, and the routed entry's `models` reads
  `complaint_triage:scripted`. Not in `evals/gate.yaml`.

### Failure drills (#60, HM-31, ADR 0027)

- `python -m hall_monitor.drills` runs the 36 synthetic claims (twice by default) through the real
  claims workflow, 8 at a time on threads, in its own registry copy, audit log and checkpoints
  under `var/drills/`. The model is scripted from the answer key.
- Injected on a seeded plan: a wrong answer code can check, wrong type, no answer, truncated
  answer, connection error, timeout, a crash after the evidence pack is logged but before the
  checkpoint is saved, duplicate concurrent submission, an owner stop at two-thirds through, and
  an optional batch cost cap. New audit event `batch_budget_reached`.
- Checked from the audit log and workflow status: every failed, crashed or stopped case ends with
  a person; clean cases finished before the stop are handled normally; no duplicate evidence packs
  or decisions; each injected fault shows by its own reason (masked faults listed separately); no
  case over its ceiling; the log verifies. Four mutation tests show the checks can fail.
- Claims workflow only.

### Agents act within their grant (#61, open, HM-32)

- `run_agent` takes the grant (`delegated`); a crew agent without one is refused before any model
  call. Every round re-checks the chain.
- `GrantBook.spend` charges each model call; past the allotment `grant_budget_reached` is logged
  and the run stops. A helper's overshoot is charged up to its parent.
- `hall_monitor/handoff.py`: `hand_off` as a tool. Code sets each helper's allotment; the task is
  fenced and escaped; the helper's answer returns as data. Not merged.

### Agentic workflows (#62, #63, #65, HM-32, ADR 0028)

Shared pattern, in `hall_monitor/agentic.py` and each workflow: a Haiku supervisor with no tools
picks one action at a time from a code-built view of codes and amounts only, with no route field
in its answer. Code refuses steps whose inputs aren't ready, repeats and invalid revisions; three
refusals send the case to a person. Every choice is logged as `supervisor_step` with no free text.
The fixed order is kept for comparison.

- **Claims (#62).** `claims_supervisor` chooses intake, coverage, risk, critic, recommendation,
  revise, finish or hand off. Budgets: 16 steps, 0.25 USD, 300 s per claim. Finish is a request:
  auto only if every required step ran on the latest inputs and the unchanged `route_claim`
  passes. Tests in `tests/test_agentic.py`; every `tests/test_pipeline.py` test runs on both paths.
  The panel's case trace shows supervisor steps.
- **Complaint desk (#63).** `complaint_supervisor` (no data classes) chooses triage, one
  independent re-check, finish or hand off. `route_triages` takes the union of reasons and the
  highest urgency; disagreement adds `triage_disagreed`, a hand-off `supervisor_handed_off`,
  finishing before triage `triage_skipped`. A complaint no agent read goes at high urgency.
  Budgets: 6 steps, 0.02 USD, 120 s. `supervisor_failed` and `agent_failed` are counted and gated
  at 0. The kept draft is the first triage's. Tests in `tests/test_desk_agentic.py`.
- **HR leave (#65).** `leave_supervisor` chooses intake, one re-check before the rules, the rules
  (code), the explanation agent, finish or hand off to HR. The rules always run on the first
  intake; a disagreeing re-check adds `intake_disagreed`. A request routed before the rules ran
  gets `assessment_skipped` and goes to an HR director. Every ending stores the evidence pack.
  Budgets: 8 steps, 0.02 USD, 120 s. Tests in `tests/test_hr_agentic.py` (33 red-team tests);
  every `tests/test_hr_agents.py` test runs on both paths.

### Complaint form (#64, HM-33, ADR 0029 Proposed)

- `python -m hall_monitor.complaints.submit --demo | --live`: a separate Starlette app modelled on
  the leave form, so the panel stays read-only.
- Takes CFPB's structured fields plus an optional narrative and builds a `Complaint` with a
  synthetic `syn-<12 hex>` ID, which can't collide with CFPB's digit-only IDs.
- Runs the real desk pipeline (agentic by default); the submitter sees only the ID and state.
  `--live` goes through the egress-guarded model client and stops at `--max-complaints` (default
  5, max 50).
- Reuses the leave form's protections: loopback only, per-run token, same-origin check, form posts
  only, body limit enforced while reading. 35 tests in `tests/test_complaint_submit.py`.

### Readiness (#66)

- `docs/readiness-checklist.md`: 44 items, each linked to its evidence, with a test keeping the
  count honest.
- Kill-switch drill in `hall_monitor/evals/stop_timing.py`, results in
  `evals/results/kill-switch-drill/`, gated.
- Generated model cards and AI inventory in `docs/model-cards.md`, with a currency test; a STRIDE
  threat model for the agentic loop; a runbook; an informal ISO/IEC 42001 and EU AI Act mapping.
- Hardening: every supervisor turn and chosen step now re-checks every agent the case used (found

## Decisions

- **The agent picks the steps; code holds the boundaries** (ADR 0028). Supervisors see codes only,
  have no route field, and can only add review; routing, budgets and the kill switch stay in code.
  Determinism is traded away: live runs of one case may take different paths at different cost.
- **Delegation only narrows** (ADR 0025): a helper's grant sits inside both its parent's grant and
  its own manifest, and over-asking is refused rather than trimmed.
- **Judge red-team results in code against human labels**, not the defence's own patterns
  (ADR 0026), after Review 20 found `must_route` had been forced to match routing.
- **Fail things on purpose, many at once** (ADR 0027), and check outcomes from the audit log, not
  the runner's own counts.
- **No shopping for an answer in HR:** the rules always run on the first intake; a disagreeing
  re-check only adds HR review.
- **Early or failed endings go to the most senior reviewer** (HR director for leave, high urgency
  for the desk), a deliberate fail-safe with an operational cost.
- **Bound every model call** at 60 s per attempt, two attempts, so one call can't blow a case's
  time budget.
- **The complaint form is new functionality**, so ADR 0029 is marked Proposed and the PR asked for
  the owner's yes before merging; it is now merged.

## Open questions

- Langfuse's older read API is removed on 2026-11-16. Any eval code that reads traces back must
  use `/api/public/v2/observations`.
- Does economy routing (Haiku for coverage and recommendation under $1,000) lose accuracy?
- The critic's main target, a live amount slip, didn't occur in 48 cap-test runs; is the seeded
  eval enough evidence?
- A crash after the evidence pack is logged but before the checkpoint is saved still needs a
  person (HM-05 gap). The drills now inject this case and confirm it ends with a person.
- The simulated override rate assumes adjusters agree with the answer key.
- The fairness eval varies names only, not pronouns.
- Claims history can't tell namesakes apart and nicknames still don't match.
- A non-USD or unextracted claim's payout is capped only by the senior adjuster's authority.
- A figure in both narrative and receipt still counts twice in the amount trace.
- The amount trace misses a bare `$` for another currency, a currency named only in a header, and
  `($20.00)` refunds (HM-04 gaps).
- Without `HALL_MONITOR_AUDIT_KEY` set, the HMAC key file sits beside the log.
- The stop owner ID is self-declared and the stop list is a file beside the code (HM-19 gaps).
- An in-flight call finishes after a stop; the drills saw up to 2 in-flight claims decided
  automatically in one run (HM-19 gap).
- Approvals pin prompts but not output schemas, request rendering or policy wording (HM-01 gaps).
- An answer that fails validation inside the SDK's parse call is billed but not recorded (HM-01).
- The final decision's signature covers the reason, so a guessed reason can be confirmed (HM-06).
- Request-information has no follow-up path.
- Entities encoded twice are decoded only once by the injection detector (HM-09 gap); the arena
  also found look-alike letters bypass it.
- The HR rules are a reading of 29 CFR Part 825 not yet reviewed by HR or an employment lawyer.
- CFPB complaints published after a pull has caught up are missed unless a pull restarts at least
  15 days back (HM-26 gap).
- CFPB labels outside the pinned snapshot are matched only by the routing patterns.
- The Langfuse client is not guarded by the egress policy; egress is allow-listed only on the
  complaint desk (readiness gap 8).
- CLAUDE.md still says "Synthetic data only", while the repo commits 500 real public complaints.
- New: desk routing reads labels and tags, not the narrative, so must-route complaints visible
  only in the narrative go to the standard queue (HM-30, 3 of 3 in the arena).
- New: the draft check misses promises in plain words and links, phones, emails or promises hidden
  with entities or full-width forms (HM-30). Drafts are still never sent.
- New: a duplicate claim submission can still run triage twice and pay twice (HM-31).
- New: a kept complaint draft may quote the typed-in text from the form (HM-33).
- New: #61 still names ADR 0028, which on `main` is now #62's ADR; it needs bringing up to date
  with `main`. A grant's case can overshoot by one call per grant in its tree.
- New: is ADR 0029 (complaint form) to be moved from Proposed to Accepted now that #64 is merged?
