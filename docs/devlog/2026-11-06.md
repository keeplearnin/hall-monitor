## What was built

### Review 6 fixes (#37–#42)

Review 6 was the whole-repo review after HM-10. Each fix was written test-first and had its own
pre-PR governance review, recorded in `docs/review/log.md`.

- **Amount trace (#37, HM-04).** The routing trace in `hall_monitor/amounts.py` now counts a
  figure only when the documents mark it as US dollars (`$`, `US$` or `USD` on the same line, no
  other currency beside it, no minus sign). Parts of dates, times and references never count.
  Before, the year in an incident date could be taken as the whole claim and paid automatically.
  A new fault (the year as the whole claim) brings the fault-injection suite to 23 faults, and
  every automatic claim is rewritten as `EUR 450`, `CAD $450` and `$450 CAD` and must go to a
  person.
- **Once-only decisions (#38, HM-05, HM-06).** `evidence_pack` and `final_decision` are once-only
  per claim, checked inside the append's `BEGIN IMMEDIATE`, so two processes can't both pay a
  claim. The audit log, not the checkpoint, decides a claim's state; `status` flags a checkpoint
  decision the log doesn't hold. A second, hand-appended pack makes the claim undecidable.
  Rejected submissions are logged as a keyed hash. Audit CLI exit codes are now 0 OK, 1 no log,
  3 tampered or unreadable, 4 busy.
- **Channel and kind (#39, HM-09).** `channel` and attachment `kind` must be known `Literal`
  values; anything else is refused on load without echoing the value. The injection detector
  scans the raw text and again after decoding HTML entities and full-width forms and dropping
  invisible characters. `escape()` now escapes `&`.
- **Kill-switch operations (#40, HM-17, HM-19).** Tests run agents from a registry copy with an
  empty stop list (`tests/fakes.py::TEST_REGISTRY_DIR`), so a committed stop no longer breaks CI.
  Stops are written under a POSIX file lock via a temporary file and swap, and through a symlink
  if there is one. The registry refuses the reserved ID `pipeline`. `live-eval.yml` runs only
  from `main`, in a `live-eval` environment.
- **Approval coverage (#41, HM-01).** The untrusted-claim notice is filled in before the prompt is
  hashed (coverage-check-v4, critic-v3; manifests 0.7.0 and 0.4.0); the prompt sent to the model
  is byte-for-byte unchanged. Requests an interrupted agent already sent are recorded once, with
  cost, as an `agent_call` event.
- **Docs against code (#42).** Docs only. "Can't merge" claims narrowed to "CI fails it" (no
  branch protection on `main`), the run-time grounding check described as it is, 10 of 19
  controls marked as having no published evidence yet, ADR count corrected to 15, and pgvector,
  DeepEval and FastAPI dropped from the Stack line.

### Read-only control panel (#44, HM-20, ADR 0016)

- New package `hall_monitor/panel/` (`app.py`, `views.py`, `pages.py`, `demo.py`, `panel.css`,
  `__main__.py`) with tests in `tests/test_panel.py`.
- Views: overview per workflow, agents, review queue, case trace, audit integrity, evals and gate,
  and the controls register.
- Each view asks the enforcing code: agent state is `Registry.require`, audit is
  `AuditLog.verify`, evals are `gate.run_gate`, and a case's route comes from its evidence pack.
- Read-only: every route is GET, every database is opened read-only (a test records each open),
  checkpoints are never opened, and a test checks no file changes after reading every page.
- No model-written free text: case traces show an allow-list of fields per event; tool arguments,
  errors, policy numbers, stop reasons, evidence packs, adjusters' reasons and signatures are
  withheld. A reason is shown only if it matches the code's own templates.
- No scripts, a content security policy, every value escaped, and it answers only on IPv4
  loopback for `localhost`/`127.0.0.1`.
- `snapshot` saves every page and its JSON as static files; `demo` runs the 36 synthetic claims
  offline with a scripted model and labels every page as demo data.
- `gate.CheckResult` keeps the metrics and meta it checked; `run_gate` takes the approvals to
  judge against. starlette, uvicorn and httpx are now declared dependencies.

### HR leave rules (#45, HM-21, ADR 0017)

- New package `hall_monitor/hr/` (`eligibility.py`, `routing.py`, `models.py`, `data.py`,
  `__main__.py`) with tests in `tests/test_hr_leave.py`. Run with `python -m hall_monitor.hr`.
- Eligibility: employer coverage, 52 weeks on the payroll (with the 7-year break rule), 1,250
  hours in the prior 12 months, and 50 employees within 75 surface miles.
- Qualifying reasons and family members, the bonding window and leave before a birth.
- Entitlement counted in workdays of the employee's normal workweek, under all four leave-year
  methods, plus military caregiver leave (26 weeks, measured forward, with other leave in an open
  period held to the combined limit).
- A missing fact is "can't decide", never a failure.
- Routing: every failed check and flag goes to HR review with the least senior role that may
  decide. Denial needs an HR manager; extending past entitlement or a retaliation risk needs an
  HR director; even a clean request is a draft for a leave specialist to sign.
- Data in `data/synthetic/hr/`: a fictional employer and 28 boundary requests with hand-worked
  answer keys, no names or diagnoses. A test fixes every record's fields.
- The panel's HR card now says the rules exist but there are no agents or cases yet.

## Decisions

- **Route only on figures marked as US dollars.** A bare number could be a date, time or
  reference; eval scoring still accepts any currency because it asks whether the figure was read
  from the documents (ADR 0001).
- **Once-only is enforced in the database transaction**, not in process memory, so it holds
  across processes. The audit log is the source of truth for a claim's state.
- **Fields that come with the claim are closed lists.** Free-form `channel` and `kind` reached
  prompts and the log unscanned; allow-listing removes the surface.
- **Detection runs on raw and decoded text**, so decoding can only add matches, after the pre-PR
  review found decoding hid phrases.
- **Tests never load the shipped registry** (one guard test excepted), so operating the kill
  switch can't break CI.
- **Live evals only from `main`**; the real protection is an environment secret, since a branch
  can edit the workflow's own guard.
- **Error text is reduced to its type in traces too**, closing the Langfuse span question.
- **The panel asks the enforcing code and changes nothing.** It reuses `Registry.require`,
  `verify` and `run_gate` rather than re-deriving state, and withholds any model-written text
  (ADR 0016).
- **HR rules first, agents later.** Eligibility, entitlement and who decides are deterministic
  code with hand-worked answer keys; missing facts mean "can't decide" (ADR 0017).

## Open questions

- Langfuse's older read API is removed on 2026-11-16. Sending traces is unaffected; any eval
  code that reads traces back must use `/api/public/v2/observations`.
- Does economy routing (Haiku for coverage and recommendation under $1,000) lose accuracy?
- The critic's main target, a live amount slip, didn't occur in 48 cap-test runs; is the seeded
  eval enough evidence, or should it be harder?
- A crash after the evidence pack is logged but before the checkpoint is saved still needs a
  person; status now reports it as `needs_a_person` (HM-05 gap).
- The simulated override rate assumes adjusters agree with the answer key; real rates are unknown.
- The fairness eval varies names only, not pronouns.
- Claims history can't tell namesakes apart (no customer ID in the data) and nicknames still
  don't match.
- A non-USD or unextracted claim's payout is capped only by the senior adjuster's authority.
- A figure written in both the narrative and a receipt still counts twice in the amount trace;
  only the total check catches a double-counted item there.
- The amount trace still misses a bare `$` used for another currency, a currency named only in a
  header, and a refund written as `($20.00)` (HM-04 gaps).
- Without `HALL_MONITOR_AUDIT_KEY` set, the HMAC key file sits beside the log.
- The owner ID on a stop is self-declared, not authenticated, and the stop list is a file beside
  the code (HM-19 gaps).
- A claim already routed for automatic handling isn't re-checked against the stop list, and a
  call already in flight finishes (HM-19 gaps).
- Approvals pin prompts but not output schemas, how requests are rendered, or the policy wording
  filled into prompts (HM-01 gaps).
- An answer that fails validation inside the SDK's parse call is billed, but its usage isn't
  recorded (HM-01 gap).
- Tool-call arguments are still logged as the model wrote them (HM-06 gap); the panel withholds
  them.
- New: the final decision's Ed25519 signature covers the reason, so anyone with the public key
  can confirm a guessed reason. Fixing it changes what is signed (HM-06 gap, ADRs 0008 and 0014).
- New: request-information has no follow-up path.
- New: entities encoded twice are decoded only once by the injection detector (HM-09 gap).
- New: the HR rules are a reading of 29 CFR Part 825 not yet reviewed by HR or an employment
  lawyer; state laws aren't modelled, only routed to a person.
