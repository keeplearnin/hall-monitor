## What was built

### One page per worked example (#81)

- `docs/examples/claims.md`, `leave.md`, `complaints.md` and `partners.md`, each with the same
  eight headings in order: why this domain, what the agents do, what code decides, who decides,
  data, results, run it, where it lives. The text is moved from the README, ADRs and design docs.
- The README's four example sections became one table showing how far each example is built and
  its live results. The crew, the red-team arena and the failure drills are named as built on an
  example, not examples of their own. The quickstart keeps the shared commands and links to each
  page's "Run it"; the repository layout gains `partners/`, `redteam/` and the data folders.
- The `new-worked-example` skill, `CLAUDE.md` and the `governance-reviewer` agent point at the
  pages, so new examples get one too.
- ADR 0001 brought in line with the routing code: it names the duplicate-documents check and
  states the header-currency and refund rules as the code has them.
- `tests/test_docs.py` checks the pages' and README's links and the example pages' headings.

### Shared records split out (#82)

- New `hall_monitor/shared_models.py` holds `AgentCall`, `ToolCall`, `StepOutcome` and
  `StepRefusal`, the only four types from `hall_monitor/models.py` used outside claims.
- `hall_monitor/models.py` keeps the claims types and imports the shared records; there is no
  re-export shim. Every import in `hall_monitor/` and `tests/` now names `shared_models`, and the
  leave, desk and partner packages and `gateway/cost.py` no longer import `hall_monitor.models`.
- `tests/test_shared_models.py` keeps every caller on `shared_models` for the four records in any
  import form, keeps example packages with their own `models.py` off the claims types, and checks
  the records are defined in `shared_models`, not re-exported (tightened in `9888519`).
- The moved classes are byte-identical apart from one comment; the JSON schema `$defs` names are
  unchanged and no approval digest depends on the module.

### ADR 0006 and the checkpoint gaps (#83, open)

- ADR 0006 no longer rests on "the steps are fixed": since ADR 0028 the supervisor picks the
  order. It now names the cost of running the supervisor's whole run as one LangGraph node: a
  crashed triage restarts from the start (`run --fresh`), reuses nothing, pays for the agents
  again, and gets a new case budget (HM-32 gap).
- The checkpoint file (`var/checkpoints.sqlite`, LangGraph msgpack, unencrypted) keeps every
  version of a claim's state, including the adjuster's name and written reasons for rejected
  decisions. Nothing deletes it once triage finishes, and `erase_evidence` doesn't reach it
  (HM-10 gap). Recorded in `controls/controls.yaml`, ADRs 0006, 0008 and 0014, the threat model,
  the board brief and readiness item 37.
- Known-limit tests in `tests/test_workflow.py` read the raw checkpoint bytes, erase a pack and
  find the checkpoint copy, and compare a crashed run's agent calls with its restart. Doc tests
  in `tests/test_docs.py` keep ADR 0006 off "fixed steps" and ADRs 0008/0014 from leaving out
  the checkpoint copy.

## Decisions

- **Each worked example gets one page with fixed headings**, so the four examples are told the
  same way and the README stays a table rather than four long sections.
- **`shared_models`, not `core`**: the name says what the module holds, next to each example's own
  `models.py`; `core` would tend to collect unrelated things.
- **No re-export shim** for the moved records: every import was changed, and a test stops new code
  from taking them from `models.py`.
- **Claims types stay in `models.py` for now**, so claims imports aren't churned twice; PR 3 moves
  them to `hall_monitor/claims/models.py`.
- **Register the checkpoint gaps before fixing them** (#83): documentation and known-limit tests
  first, with the fix (a graph per supervisor step, or deleting and encrypting checkpoints) left
  for a later PR.

## Open questions

- Langfuse's older read API is removed on 2026-11-16. Any eval code that reads traces back must
  use `/api/public/v2/observations`.
- Does economy routing (Haiku for coverage and recommendation under $1,000) lose accuracy?
- The critic's main target, a live amount slip, didn't occur in 48 cap-test runs; is the seeded
  eval enough evidence?
- A crash after the evidence pack is logged but before the checkpoint is saved still needs a
  person (HM-05 gap).
- New (#83): a crashed claims triage restarts from the start, pays for every agent again and gets
  a new case budget, so one claim's spend is bounded only by how often it is restarted (HM-32 gap).
- New (#83): the claims checkpoint file is unencrypted, keeps claim text and adjusters' written
  reasons, and is never deleted or reached by `erase_evidence` (HM-10 gap).
- New (#82): the leave, desk and partner pipelines still load `hall_monitor.models` at run time
  through `hall_monitor/agents/base.py`, and `gateway/redaction.py`, `gateway/injection.py` and
  `governance/audit.py` still use claims types (for PR 3).
- The simulated override rate assumes adjusters agree with the answer key.
- The fairness eval varies names only, not pronouns.
- Claims history can't tell namesakes apart and nicknames still don't match.
- A non-USD or unextracted claim's payout is capped only by the senior adjuster's authority.
- A figure in both narrative and receipt still counts twice in the amount trace.
- HM-04 amount-trace gaps: accounting refunds and a currency named anywhere in the documents are
  handled (#80); still open are a bare `$` with no other currency named, a spaced dash
  (`– $20.00`), and currency names that are also words over-flagging.
- Duplicate documents are caught only after triage finishes (two at once can miss), on the same
  extracted policy, attachments only, and in the workflow only. A duplicate submission can still
  run triage twice (HM-31).
- Without `HALL_MONITOR_AUDIT_KEY` set, the HMAC key file sits beside the log.
- The stop owner ID is self-declared and the stop list is a file beside the code (HM-19 gaps).
- An in-flight call finishes after a stop (HM-19 gap).
- Approvals pin prompts but not output schemas, request rendering or policy wording (HM-01 gaps).
- An answer that fails validation inside the SDK's parse call is billed but not recorded (HM-01).
- The final decision's signature covers the reason, so a guessed reason can be confirmed (HM-06).
- Signatures prove only that a key signed the bytes, and the keys are public demo keys (HM-05,
  HM-23).
- Request-information has no follow-up path.
- The injection detector and the draft check are wider (#80) but still pattern lists (HM-09,
  HM-30).
- Desk routing reads labels and tags, not the narrative, so must-route complaints told only in
  the narrative go to the standard queue (3 of 18 in the arena).
- A changed complaint is re-routed only if a manual `--since` pull fetches it; ingest's cursor
  only moves forward.
- The HR rules and roles are a reading of 29 CFR Part 825 not yet reviewed by HR or an
  employment lawyer.
- CFPB complaints published after a pull has caught up are missed unless a pull restarts at
  least 15 days back (HM-26 gap).
- CFPB labels outside the pinned snapshot are matched only by the routing patterns.
- The Langfuse client is not guarded by the egress policy (readiness gap 8).
- CLAUDE.md still says "Synthetic data only", while the repo commits 500 real public complaints.
- A kept complaint draft may quote the typed-in text from the form (HM-33).
- Is ADR 0029 (complaint form) to be moved from Proposed to Accepted?
- Who owns the spending caps and at what level? The partners caps (1.00 a day, 10.00 a month)
  are estimates, not measured.
- The spend ledger covers one machine, and the evals' live runs aren't held to the caps yet
  (HM-34 gaps).
- Review 27: the supervisor loop is written three times (claims, desk, HR), and one stop reason
  reads a misleading "unexpected UnpricedModelError".
- HM-35 gaps: a case can overshoot by one call per grant; a call billed and then raised on isn't
  charged; the grant book lives in memory; a helper meant to see less personal data needs
  code-built input. A workflow's case budget doesn't see helpers' spending between rounds.
- Whether a crew lead treats a helper's answer as data rests on its prompt.
- Partner agents' line categories and competitor and public-sector flags are trusted, not
  checked against the documents (HM-37).
- Partner redaction is pattern-based and doesn't remove names (HM-37).
- A partner claim with dates read correctly but before approval goes to review, not to the hold
  it would get if the rules re-derived `activity_before_approval`.
- A claim in the partner book with a bad reference still stops the book loading (HM-36).
- The live leave run has no repeat runs to measure variation, and no findings note was published
  beside it (HM-18 gap).
