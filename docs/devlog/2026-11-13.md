## What was built

### Time and cost budget inside a specialist's tool loop (#68, review 27)

- The problem: `hall_monitor/agentic.py` checked the claim's budget only before each agent
  started. Coverage, risk and the critic can each send up to `MAX_TOOL_ROUNDS + 1` = 7 requests,
  each bounded at about 2 minutes live, so one agent could run about 14 minutes past the 300 s
  budget.
- `ToolAccess.check_budget` (`hall_monitor/agents/base.py`) now runs before each later tool
  round, with the rounds that agent has already sent. The kill-switch check still comes first.
- `_check_spend(ctx, sent)` adds those rounds' cost to the claim's. On a budget stop mid-loop the
  rounds already sent stay in the record, once, and the failed step's cost includes them.
- Overshoot is now at most the one request in flight. Only the agentic claims path changes; desk
  and HR agents have no tools, so their overshoot was already one request.
- Tests in `tests/test_agentic.py`: `test_the_time_budget_holds_inside_a_specialist_s_tool_loop`
  (7 rounds ran before the fix; now 3 run, then the claim stops for a person) and
  `test_the_cost_budget_counts_the_rounds_a_specialist_has_already_sent`.
- Docs: ADR 0028, the HM-32 gaps in `controls/controls.yaml`, readiness checklist item 6, threat
  model row D, review log.

### Cost governance, slice 1 (#69, HM-34, ADR 0030)

- `registry/budgets.yaml`: each workflow's case budget (steps, USD, seconds), daily and monthly
  caps, owner, and the model price table. Approved by digest in `registry/approvals.yaml` like a
  hall pass (`python -m hall_monitor.approvals`); comments and layout don't count as a change.
  Owners must be in `owners.yaml` and the caps must be consistent with each other.
- `hall_monitor/budgets.py` loads it. The claims, desk and leave pipelines read their case budget
  from it at the start of every case, before any model call; the old `Limits`, `DeskLimits` and
  `LeaveLimits` defaults stay for tests, with a test keeping them equal to the file.
- `hall_monitor/gateway/cost.py` takes prices from the approved file and reloads them when it or
  `approvals.yaml` changes. An unapproved file means no model has a price, so every case goes to a
  person.
- `hall_monitor/spend.py`: a SQLite ledger at `var/spend.sqlite`, shared by every process on the
  machine. Each case reserves its whole budget inside `BEGIN IMMEDIATE` and settles at actual cost
  when it ends; a crash, interruption, unpriced cost or failed settle leaves the reservation
  counting in full. Days and months are UTC. The ledger holds workflow names, case IDs, amounts and
  times only.
- A refused case (over a cap, budgets unapproved, or ledger unreachable) goes to a person with no
  model call: a claim to an adjuster; a complaint to specialist review with reason `spend_refused`
  (high urgency on the agentic path); a leave request to an HR director with its evidence pack
  stored. Reasons are fixed templates and the panel shows them (`hall_monitor/panel/views.py`).
- Live entry points pass the ledger: `hall_monitor.run`, `complaints.run --live`,
  `complaints.submit --live`, `hr.run`, `hr.submit --live`. Demo and scripted runs aren't counted.
- `tests/test_spend.py`: 64 offline tests, including a 40-thread race for the last of a cap,
  each workflow at the cap (agentic and fixed), and each live entry point refused at the cap.
- Docs: ADR 0030, HM-34 in the controls register, README controls row and roadmap item 26,
  readiness checklist item 7, the desk design's reasons table.

## Decisions

- **Spending limits are approved, not defaults** (ADR 0030). Budgets, caps, owners and prices
  move into one file approved by digest, so a change is a reviewed approval rather than a code
  edit, and an unreviewed edit refuses every case.
- **Reserve the whole case budget up front, settle later.** Each case takes its full budget
  against the cap inside `BEGIN IMMEDIATE`, so concurrent processes can't both take the last of a
  cap; anything that goes wrong leaves the reservation counting in full, erring toward spending
  less.
- **Refused means a person, never a silent drop.** Over a cap, unapproved budgets or an
  unreachable ledger all route the case to a person with no model call (an adjuster, specialist
  review, or an HR director).
- **Caps apply to live entry points only** in slice 1; demo and scripted runs aren't counted.
- **Check the budget every tool round, not just every agent** (#68), so the overshoot is bounded
  by one request in flight rather than a whole specialist's loop.
- **Keep reportlab out of the project's dependencies**, running the PDF generator with
  `uv run --with reportlab`, and draw the controls page from `controls.yaml` so it can't drift.
- **Docs say no more than the code does** (Review 29): for example, the complaint desk is rated
  partial and the caps are described as applying to live runs only.
