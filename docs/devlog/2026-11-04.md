## What was built

### Milestone 11: hardening from the claims audit (#23)

- **Audit events as they happen.** Triage reports each agent call, tool call, review, revision
  and correction through `on_event`; the workflow's `TriageRecorder` appends it at once. A run
  that dies part-way leaves its trail, and a claim whose events can't be recorded doesn't proceed.
- **Evidence stored by hash.** Evidence packs live in the audit database under their SHA-256.
  Before a decision the review step checks the checkpoint's pack against the recorded hash and
  the stored copy; `verify` reports a changed pack and lists erased ones without failing the chain.
- **Signed adjuster decisions.** `hall_monitor/governance/signing.py`: a decision is accepted only
  with an Ed25519 signature over the claim, every decision field and the evidence hash. The two
  fictional adjusters in `registry/adjusters.yaml` use public demo keys (`demo_key: true`); the
  review CLI takes `--key` for a real one. ADR 0014 records this.
- **No personal data in decision entries.** The log keeps the adjuster's ID and a hash of the
  reason, not the name or reason text.
- **Data classes enforced at run time.** Agent inputs and tools declare what they carry; anything
  beyond the manifest is refused before the model or tool is called.
- **More redaction.** `gateway/redaction.py` now covers attachment file names and tool results.
- 15 new tests across `test_audit.py`, `test_pipeline.py`, `test_privacy_security.py` and
  `test_workflow.py`. ADRs 0006, 0008, 0009, the controls register and README updated.

### Review 3 fixes (#24) and `CLAUDE.md`

- `governance/routing.py` checks the claim against the policy record: claimant must be the
  insured, incident inside the coverage period; no policy record, no incident date or a non-USD
  claim goes to a person. Economy routing applies to USD claims only.
- An unpriced model stops the claim instead of crashing (`gateway/cost.py`); a test checks every
  approved model is priced.
- The eval gate compares each result's prompt-template hash with the approval. A shared
  `evals/meta.py` records run metadata for every runner, so adversarial and fairness results can
  count as current.
- `audit verify` reports malformed evidence entries and removed triggers instead of crashing; the
  audit CLI opens the log read-only. Crashed claims can be resubmitted. One evidence-hash definition.
- `critic_seeded` no longer divides by zero and exits non-zero on errors; a failed fairness run no
  longer loses the others.
- `CLAUDE.md` records the commands and rules (no API calls in tests or CI, merge commits, version
  bumps and re-approval for prompt or manifest changes, docs kept current, nothing personal in
  logs).

### Phase A1: approval rules (#25)

- Paying a claim the AI never assessed for fraud (a stopped claim) needs a senior adjuster.
- Denying above an adjuster's authority limit needs a senior adjuster.
- Demo-key signatures are marked (`signed_with_demo_key`) in the final decision and audit entry.
- `review show` serves the evidence pack stored under the hash recorded at triage and warns if
  the checkpoint copy changed.
- One `changes_ai` rule for validation and the recorded `overrode_ai`; `final_auto` raises
  `ValueError` instead of using `assert`.
- 9 new tests, mostly in the new `tests/test_approval_rules.py`.

### Phase A2: audit log (#26)

- Adjuster reasons and critic issues stored as HMAC-SHA256 (`reason_hmac`, `problem_hmac`). The
  key comes from `HALL_MONITOR_AUDIT_KEY` or an owner-only file beside the log, created on first
  use.
- Every `AuditLog` read takes the same re-entrant lock as writes. A new test with three writer
  and three reader threads failed before the change (`verify` read a half-written entry).

### Phase A3: gateway and tools (#27)

- A tool call that fails after it was allowed is recorded before the error propagates.
- The gateway runs inside a running event loop (worker thread with its own loop).
- Agents are only offered tools their data classes allow; redactions are counted per `ToolCall`.
- `claims_history` matches names ignoring case, accents, spacing and punctuation.
- The recommender's manifest adds `health` (version 0.4.1, re-approved in
  `registry/approvals.yaml`): its claim type and clause numbers can reveal a medical claim.

### Phase A4: evals (#28)

- `amount_in` in `evals/scoring.py` finds whole amounts without cents (`$1,000`, `1000`) and never
  matches inside another amount (`1,100`, `1,000.50`).
- `is_infrastructure_stop`, shared by the baseline, adversarial and fairness runners: API failures
  and our own errors count as eval errors, not safe stops.
- The fairness runner takes each claim's policy from its answer key and doesn't swap a name right
  before a number (`June 14`). `waiting()` reads one row per claim.
- The review log records all 32 review-3 findings as fixed.

### Governance review agent (#29)

- `.claude/agents/governance-reviewer.md`: a read-only Claude Code subagent that reviews a
  branch's diff or the whole repo for governance rules, line-level correctness, adversarial test
  coverage, docs that overclaim, and cleanup. Each finding is verified (CONFIRMED or PLAUSIBLE)
  and reported with severity, a failure scenario and the test that would catch it. It never calls
  the Anthropic API.
- `CLAUDE.md` now says to run it before each PR and on the whole repo at the end of each phase,
  and that fixes are test-first.

### Phase A5: end-of-phase review (#30)

The agent's whole-repo review found 10 issues, and its pre-PR review of the branch 3 more:

- A non-USD claim, or one with no amount extracted, needs a senior adjuster to pay or deny.
- Paying a claim with above-low risk needs a senior adjuster, even with no fraud flag.
- Amounts must be finite (`allow_inf_nan=False`); NaN made every routing comparison false.
- One `name_key` in the new `hall_monitor/names.py` for routing and claims history.
- An unfinished triage restarts only on request (`restart=True`, `run --fresh`), so a run in
  progress isn't raced.
- Refused hall passes and any "cost unknown" stop count as eval errors.
- `audit verify --expect-seq 0` no longer skips the anchor check.
- ADR 0001 lists every routing check, and `tests/test_docs.py` keeps it so. Review 4 is in the
  review log.

### Phase B1: fault injection (#31)

- `tests/test_agent_faults.py`: 22 kinds of wrong answer (wrong claimant, another insured's
  policy, dates outside cover, another currency, invented or double-counted amounts, payouts above
  the claim or threshold, a fraud flag labelled low, a wrong recommendation, a critic never
  satisfied), each on the 16 claims the answer key routes automatically. Each agent in turn also
  returns nothing, the wrong type or an unfinished turn, fails at the API, or raises. 389 cases.
- What broke, fixed test-first:
  - **High:** invented or inflated amounts that coverage paid in full routed automatically. The
    new `hall_monitor/amounts.py` traces each claimed item to its own occurrence in the redacted
    claim documents, requires the total to appear there, and checks the items add up. Eval
    scoring uses the same rule.
  - **Medium:** `run_agent` passed through unknown stop reasons such as `pause_turn`; only
    `end_turn` counts now.
  - **Medium:** an answer of the wrong type crashed the stop path; `run_agent` now refuses it.
- The pre-PR review confirmed 5 findings; the most serious was that the first amount trace could
  be fooled by a duplicated item, a total line or a date. All fixed or logged as gaps. The fake
  client now takes a stop reason per agent.

## Decisions

- **Adjuster decisions are signed with Ed25519** over the claim, decision fields and evidence
  hash (ADR 0014), so the record proves who decided what on which evidence. Demo keys are public
  and marked, not passed off as real.
- **Keyed hashes (HMAC) for reasons and critic issues**, not plain SHA-256, so a guessed reason
  can't be confirmed by hashing it.
- **Audit events are written as they happen**, and a claim whose events can't be recorded stops,
  so a crash can't erase the trail.
- **Fixes are test-first**, and a `governance-reviewer` agent runs before every PR and at the end
  of each phase (`CLAUDE.md`).
- **Amounts that can't be checked go to a senior adjuster.** Non-USD and unextracted claims
  can't be compared with USD limits, so they need senior authority rather than a guessed
  conversion.
- **Only `end_turn` counts as a finished answer**; anything else stops the claim.
- **Every claimed amount must trace to the claim documents**, in the same redacted text the
  pipeline sees, and scoring uses the same rule as routing so the two can't drift.
- **Errors code can't see are pinned as known limits** (a missed fraud signal, an overpayment
  within the amount claimed) and logged as HM-04 gaps rather than claimed as covered.
- **The recommender's input is treated as health data**, since claim type and clause numbers can
  reveal a medical claim; this needed a version bump and re-approval.

## Open questions

- Langfuse's older read API is removed on 2026-11-16. Sending traces is unaffected; any eval
  code that reads traces back must use `/api/public/v2/observations`.
- Does economy routing (Haiku for coverage and recommendation under $1,000) lose accuracy?
- The critic's main target, a live amount slip, didn't occur in 48 cap-test runs; is the seeded
  eval enough evidence, or should it be harder?
- A crash between a decision event and the checkpoint save could log a decision twice (carried
  forward; today's work didn't say it was resolved).
- The simulated override rate assumes adjusters agree with the answer key; real rates are unknown.
- The fairness eval varies names only, not pronouns.
- Claims history can't tell namesakes apart (no customer ID in the data) and nicknames still
  don't match.
- A non-USD or unextracted claim's payout is capped only by the senior adjuster's authority.
- A figure written in both the narrative and a receipt still counts twice in the amount trace;
  only the total check catches a double-counted item there.
- Without `HALL_MONITOR_AUDIT_KEY` set, the HMAC key file sits beside the log.

Resolved today: audit events are now written as they happen (M11), and adjuster reasons are no
longer stored as written (hashed in M11, keyed in A2).
