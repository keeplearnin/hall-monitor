# 2026-11-11: The complaint desk on public CFPB data, built in four slices with a no-send rule in code

## Summary

A third worked example landed in one day: a simulated company complaint desk on the public CFPB
Consumer Complaint Database (roadmap milestone 21). It was built as four stacked PRs (#52–#55,
HM-25 to HM-28): first a hard rule that the system never replies to or sends anything to anyone,
then ingestion with pinned snapshots, triage with routing in code, and evals, fairness checks, a
CI gate and a panel page. A fifth PR (#56) makes the panel say who answered each complaint. All
five are merged; tests went from 1,873 (#52) to 2,363 (#56), all offline. The triage model has not
been run live.

## What was built

### Design and the no-reply, no-send rule (#52, HM-25, ADR 0021)

- `docs/complaint-desk-design.md` sets out the desk. CFPB's API and bulk download no longer
  publish consumer narratives (checked 2026-11-11), so triage runs on structured fields: product,
  issue, sub-issue, tags, state, ZIP prefix and submission channel. The narrative field stays
  optional.
- `hall_monitor/egress.py`: one outbound data path. It allows a GET over https to
  `www.consumerfinance.gov` under the complaint API path and nothing else; other hosts, ports,
  schemes, URL credentials, normalising paths and methods are refused before sending, redirects
  are never followed, and each refusal is logged as `egress_refused`. The desk's model client is
  guarded to `POST /v1/messages` only.
- `hall_monitor/no_send.py`: the registry refuses a send-capable manifest at run time
  (`SendCapabilityError`), approvals refuse to approve one, and the tool gateway won't start on or
  call such a tool.
- `hall_monitor/complaints/drafts.py`: a draft has no address, recipient or channel field, and
  `never_sent` can only be `True`. Drafts are stored by hash as evidence.
- `python -m hall_monitor.no_send check`, a new CI step, reads the AST of every module and
  `pyproject.toml` and fails on mail, messaging or raw-network libraries, HTTP clients outside
  `egress.py`, HTTP writes, fastmcp clients or proxies, dynamic imports, shell commands and
  sending dependencies. The docs call it a tripwire, not a proof.
- Shared core: `ToolGateway` now takes its server, data classes and pipeline tools as arguments
  (defaulting to claims), `Registry.require` checks every manifest against the catalogue, and
  `draft_stored` is an evidence event. Tests in `tests/test_no_send.py`.

### Ingestion with snapshots (#53, HM-26, ADR 0022)

- `hall_monitor/complaints/` gains `cfpb.py`, `ingest.py`, `models.py` and `store.py`; tests in
  `tests/test_complaint_ingest.py`.
- Reads go through one read-only MCP tool, `cfpb_complaint_search`, behind `ToolGateway`; only
  the pipeline may call it, and `CfpbClient` in `egress.py` makes the GETs.
- One request per second; retries with backoff and jitter on timeouts, 429 and 5xx, honouring
  `Retry-After` up to a cap. Egress refusals and other 4xx are never retried.
- Incremental pulls oldest first with a `search_after` cursor that moves only after a page is
  processed; `--every 6h` repeats.
- Minimised at the door: a field allow-list (company name never enters), ZIP cut to three digits,
  credit reporting excluded.
- Strict validation (dates need a time zone), dedupe by complaint ID with versions for changes,
  and quarantine logging field names and error types only.
- Every page is snapshotted with a hash manifest. The pinned snapshot
  `data/cfpb/snapshots/2026-10-01` holds 500 real, public, minimised complaints, and its manifest
  hash is recorded in code. README and HM-18 name this as the one exception to "all data is
  synthetic".

### Triage with routing in code (#54, HM-27, ADR 0023)

- `complaints/routing.py` sends to specialist review at high urgency, whatever the agent says:
  fraud and unauthorised transactions, identity theft, foreclosure or mortgage hardship,
  discrimination, and complaints tagged Older American or Servicemember. Untimely responses, text
  aimed at the AI, agent failure, low confidence, an urgency below the code's floor, an extra
  agent concern, and an interrupted triage also go to specialist review. Everything else goes to
  the standard queue, still worked by a person. Nothing is resolved automatically.
- `complaints/triage_agent.py`: the `complaint_triage` agent (Haiku, no tools, manifest v0.1.0 in
  `registry/complaint_triage.yaml`, fictional owner, approval in `registry/approvals.yaml`). It
  never sees the complaint ID, state or ZIP prefix, can only add concerns or raise urgency, and a
  failure never invents an answer.
- Drafts are dropped if they promise a refund, credit, waiver, fix or deadline, or carry a link,
  domain, email address or phone number.
- `complaints/pipeline.py`: each complaint is claimed once before the model call, and a crash or
  killed run still ends in specialist review. The audit log holds IDs, hashes, codes and cost,
  never summary or draft text.
- `complaints/run.py`: `--demo` runs the pinned snapshot offline with the scripted stand-in
  (`complaints/scripted.py`); `--live --limit N` calls the API. Tests in
  `tests/test_complaint_triage.py`.

### Evals, fairness, gate and panel page (#55, HM-28, ADR 0024)

- `python -m hall_monitor.complaints.evals` runs all 500 snapshot complaints and scores routing
  against the hand-written key `data/cfpb/label_reasons.yaml`, not against the routing patterns.
- `evals/gate.yaml` gains a complaint desk check: no must-route complaint missed, below high
  urgency or missing its reason; every untimely complaint in specialist review; no errors or agent
  failures; no stored draft with a delivery path; zero counterfactual flips; and results of the
  mode the check names. The live check also gates egress refusals.
- Fairness: changing state or ZIP prefix must change neither the code's reasons nor the agent's
  input (gated, and documented as unable to flip by construction). Group rates by ZIP region and
  tag are reported, not gated.
- `hall_monitor/panel/desk.py`: a read-only Complaint desk page with the queue and routing reasons
  in the code's words, urgency and cost, pulls, claimed-but-unrouted complaints, and the no-send
  control's status. The panel demo includes 60 scripted complaints.
- Published result in `evals/results/complaints-scripted/`. Tests in
  `tests/test_complaint_evals.py`.

### Who answered (#56)

- The desk page has an "Answered by" column: `scripted`, `model`, `unknown` (never assumed to be
  the model), `no answer` and `not yet`. Only `model` gets a green badge.
- A banner appears whenever any answer on the page is scripted.
- The page names the audit log it reads by repo path and lists where pulls, the complaint demo and
  the panel demo each write.

## Decisions

- **Never reply, never send, enforced in code.** One allow-listed egress path, a read-only tool
  catalogue, drafts with no delivery fields, and a static CI check (ADR 0021). What still leaves
  the machine is stated: model calls to the Claude API and metadata-only Langfuse traces.
- **Triage on structured fields**, because CFPB stopped publishing narratives.
- **Commit one pinned snapshot of real, minimised public data** so evals and demos replay offline
  and reproducibly; its hash is pinned in code (ADR 0022).
- **Every complaint goes to a person.** Code sets the floor on routing and urgency; the agent can
  only raise them (ADR 0023).
- **Score routing against a hand-written key**, not the patterns, so a weaker pattern shows up in
  the eval (ADR 0024).
- **Never label an answer as the model's unless the log says so.** Unknown stays unknown (#56).

## Open questions

- Langfuse's older read API is removed on 2026-11-16. Any eval code that reads traces back must
  use `/api/public/v2/observations`.
- Does economy routing (Haiku for coverage and recommendation under $1,000) lose accuracy?
- The critic's main target, a live amount slip, didn't occur in 48 cap-test runs; is the seeded
  eval enough evidence?
- A crash after the evidence pack is logged but before the checkpoint is saved still needs a
  person (HM-05 gap).
- The simulated override rate assumes adjusters agree with the answer key.
- The fairness eval varies names only, not pronouns.
- Claims history can't tell namesakes apart and nicknames still don't match.
- A non-USD or unextracted claim's payout is capped only by the senior adjuster's authority.
- A figure in both narrative and receipt still counts twice in the amount trace.
- The amount trace misses a bare `$` for another currency, a currency named only in a header, and
  `($20.00)` refunds (HM-04 gaps).
- Without `HALL_MONITOR_AUDIT_KEY` set, the HMAC key file sits beside the log.
- The stop owner ID is self-declared and the stop list is a file beside the code (HM-19 gaps).
- A claim already routed for automatic handling isn't re-checked against the stop list, and an
  in-flight call finishes (HM-19 gaps).
- Approvals pin prompts but not output schemas, request rendering or policy wording (HM-01 gaps).
- An answer that fails validation inside the SDK's parse call is billed but not recorded (HM-01).
- The final decision's signature covers the reason, so a guessed reason can be confirmed (HM-06).
- Request-information has no follow-up path.
- Entities encoded twice are decoded only once by the injection detector (HM-09 gap).
- The HR rules are a reading of 29 CFR Part 825 not yet reviewed by HR or an employment lawyer.
- New: CFPB publishes a complaint after the company responds or about 15 days. A complaint
  published after a pull has caught up is missed unless a pull restarts at least 15 days back,
  and nothing schedules that (HM-26 gap).
- New: CFPB labels outside the pinned snapshot are matched only by the routing patterns, not the
  hand-written table.
- New: the Langfuse client is not guarded by the egress policy.
- New: CLAUDE.md still says "Synthetic data only", while the repo now commits 500 real public
  complaints.
