## What was built

### Kill switch (#33, HM-19, ADR 0015)

- **Owners are people.** Each manifest's `owner` is an ID from the new `registry/owners.yaml`
  (two fictional people), checked when the registry loads. All five manifests got a minor version
  bump and a new approval in `registry/approvals.yaml`; the prompts didn't change.
- **Stopping needs no approval.** `python -m hall_monitor.kill_switch stop <agent> --by <owner-id>
  --reason ...` appends to `registry/stops.yaml`, after refusing an unknown agent or person.
  `hall_monitor/kill_switch.py` is new.
- **A stop applies on the next call.** `Registry.require` in `hall_monitor/registry.py` reads the
  stop list on every check. `run_agent` (`agents/base.py`) checks again before each later tool
  round, and `pipeline.py` checks every agent the result rests on just before routing.
- **The stop list fails closed.** Missing, unreadable or non-UTF-8, a duplicate YAML key, an
  unknown agent, an unlisted person, or an approval clearing a stop the list doesn't hold: each
  refuses every agent.
- **Restarting needs review**: the stop must be listed under `cleared_stops` in
  `registry/approvals.yaml` (`python -m hall_monitor.approvals --resume STOP_ID`).
- **Stops are never deleted.** A new CI step in `.github/workflows/ci.yml` fails a PR that removes
  or edits a stop. `.github/CODEOWNERS` leaves `stops.yaml` without an owner and now covers
  `/hall_monitor/` and `/.github/`; a test pins this.
- Refusals, and so the audit log, carry only the stop ID and owner ID, not the reason or a
  hand-typed agent name.
- `tests/test_kill_switch.py` (new). README, `docs/controls.md`, `controls/controls.yaml`, the
  board brief, business summary and HM-01 gaps updated. The kill switch is no longer listed under
  milestone 12 in the README roadmap.

### Review 5 fixes (#34)

- `run --fresh` (`run.py`) calls `submit(restart=True)` instead of deleting saved state, so it
  restarts only a triage that never finished.
- `submit` (`workflow.py`) refuses any claim whose evidence pack is already in the audit log, so a
  new or deleted checkpoints file can't re-triage a decided claim.
- The review step checks the saved triage result against the `result_sha256` logged at triage
  before the approval rules read it. A result edited until it no longer parses is a recorded
  rejection, not a crash. ADR 0014 corrected.
- Rejections (`governance/approval.py`, `governance/audit.py`) name adjusters by ID, don't repeat
  an unregistered ID, and summarise a malformed submission by pydantic error type.
- `IntakeExtraction` in `models.py`: currency must match `^[A-Z]{3}$` and the policy number must
  be code-shaped; an answer that isn't stops the claim.
- An unforeseen error stops the claim with its type only (`pipeline.py`), since its text can
  repeat model-written tool arguments.
- Tests added in `test_audit.py`, `test_intake.py`, `test_pipeline.py` and `test_workflow.py`.
  Review 5 and its pre-PR review are in `docs/review/log.md`.

### Bank and tax ID redaction (#35, open)

- `gateway/redaction.py` removes tax IDs after a TIN, EIN, ITIN or tax ID label; bank account
  numbers after labels such as "account number", "acct #" or "A/C no." (only the last four digits
  after "account ending"); routing numbers after "routing", "ABA" or "RTN"; and IBANs that pass
  the mod-97 checksum, checked before card detection.
- Every run between a label and its number is bounded, after the pre-PR review found cubic
  backtracking.
- Tests in `test_privacy_security.py`. README, ADR 0009, business summary and HM-10 updated.

## Decisions

- **Stopping is cheap, restarting is reviewed.** A wrong stop fails safe, so any listed owner can
  stop any agent with no approval; clearing a stop goes through `approvals.yaml` (ADR 0015).
- **The stop list fails closed.** Any doubt about it (unreadable, duplicate keys, unknown names,
  a clearance with no matching stop) refuses every agent.
- **Stops are append-only**, enforced in CI, and the code and CI that enforce it have code
  owners, so one PR can't remove both a stop and the check.
- **A finished claim is judged from the audit log, not the checkpoint**, because checkpoints can
  be deleted or replaced.
- **Model output that reaches the log must be code-shaped**, and error text is reduced to its
  type, so free text written by the model doesn't land in routing reasons or evidence packs.
- **Bank and tax IDs are redacted only when labelled.** An unlabelled run of digits could be an
  amount, date, invoice or booking number; the misses are listed as HM-10 gaps.

## Open questions

- Langfuse's older read API is removed on 2026-11-16. Sending traces is unaffected; any eval
  code that reads traces back must use `/api/public/v2/observations`.
- Does economy routing (Haiku for coverage and recommendation under $1,000) lose accuracy?
- The critic's main target, a live amount slip, didn't occur in 48 cap-test runs; is the seeded
  eval enough evidence, or should it be harder?
- A crash between a decision event and the checkpoint save could log a decision twice. Related:
  a crash after the evidence pack is logged but before the checkpoint is saved now needs a person
  (HM-05 gap).
- The simulated override rate assumes adjusters agree with the answer key; real rates are unknown.
- The fairness eval varies names only, not pronouns.
- Claims history can't tell namesakes apart (no customer ID in the data) and nicknames still
  don't match.
- A non-USD or unextracted claim's payout is capped only by the senior adjuster's authority.
- A figure written in both the narrative and a receipt still counts twice in the amount trace;
  only the total check catches a double-counted item there.
- Without `HALL_MONITOR_AUDIT_KEY` set, the HMAC key file sits beside the log.
- New: the owner ID on a stop is self-declared, not authenticated, and the stop list is a file
  beside the code; a deployment would need a store owners can write to at once (HM-19 gaps).
- New: the workflow's automatic finish, just after routing, isn't re-checked against the stop
  list, and a call already in flight finishes (HM-19 gaps).
- New: Langfuse may record an exception's message on a span, so failed model output could reach
  traces (plausible, not confirmed or fixed).
- New: approvals pin prompts but not output schemas, and the API sends the new pydantic patterns
  to the model as description text; answers like `usd` now stop the claim, which changes live
  eval behaviour (HM-01 gap).
- New: tool-call arguments are still logged as the model wrote them (HM-06 gap).
