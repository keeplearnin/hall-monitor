# 2026-11-03: Milestone 1 lands

## Summary

hall-monitor went from a README-only repo to a working milestone 1: an agent registry that
refuses agents without a hall pass, a synthetic travel-insurance dataset with ground truth, and
an intake agent that runs live on Claude Haiku 5.5, traced in Langfuse. Two PRs merged to `main`.

|---|---|---|

## What was built

**Agent registry (hall passes).** YAML manifests in `registry/` for all five agents (intake,
coverage check, critic, risk and fraud, recommendation). Each names an owner, risk tier, status,
model, tool allow-list and the sensitive data classes it may see. The registry refuses:

- agents with no manifest,
- agents whose status isn't `active` (only `intake` is active; the rest are `planned`),
- tools the manifest doesn't list.

Each manifest has a SHA-256 digest so a run can prove which hall pass it ran under. The JSON
schema is published in `registry/agent_manifest.schema.json`, and a test fails if it drifts.

**Synthetic dataset.** A fictional policy wording (Wayfarer Travel Protection, from fictional
insurer Lantern Ridge Mutual) with numbered clauses and Essentials / Plus plans; six policy
records; six claims with full ground truth (extraction, coverage decision with clauses and
reasoning, risk flags, next step, route):

| Claim | Scenario | Expected |
|---|---|---|
| 001 | Trip cancelled for appendicitis | Pay 1,992, auto |
| 002 | Bag delayed 30 hours | Pay 282.49, auto |
| 003 | Wrist fracture on a marked trail | Pay 6,480, adjuster (over threshold) |
| 004 | Crohn's flare-up, pre-existing | Deny, adjuster |
| 005 | Lost laptop, receipt dated after the loss | Investigate, adjuster |
| 006 | Same receipt submitted twice | Pay 100, adjuster |

Routing rule: adjuster for denials, investigations, any fraud flag, or payouts above USD 2,500.

**Intake agent.** Claude Haiku 5.5 with structured outputs, so the reply must match the
`IntakeExtraction` schema. Claim text is fenced as untrusted data; refusals and truncated
output raise errors.

**Tracing.** Langfuse, on only when both keys are set. The intake span records claim ID, agent
version, model, manifest digest and prompt version; the Anthropic SDK's own span carries token
usage.

**Project.** uv, Python 3.12, Apache 2.0 `LICENSE`, `.env.example`, run CLI, 33 offline tests
(registry refusals, dataset consistency, routing rule, intake with a fake client), ruff clean.

## First live results

| Claim | Result |
|---|---|
| 001 | Matches ground truth on every field except `incident_location` |
| 006 | Matches; lists the duplicate receipt as two items, as instructed |

About 2,100 input and 700 output tokens per claim on Haiku.

## Decisions

- **Intake reports what the customer claimed; it doesn't judge.** Duplicates and fraud are for
  the risk and fraud agent.
- **Inactive agents can't run.** Planned agents have manifests now, so the registry's shape is
  settled before their code exists.
- **Add dependencies with the milestone that uses them.** LangGraph, fastmcp and Postgres aren't
  installed yet.
- **Usage lives on the SDK's span.** The Anthropic SDK (2.4) emits its own Langfuse generation;
  logging usage on ours as well double-counted every run (fixed in #2).

## Open questions

- Should `incident_location` accept a facility name ("St. Bartholomew's Hospital") when no city
  is given? Ground truth says null. Decide how to score it before the milestone 2 baseline.
- Langfuse's older read API is removed on 2026-11-16. Sending traces is unaffected; any eval
  code that reads traces back must use `/api/public/v2/observations`.
