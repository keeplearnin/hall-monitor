## What was built

### Milestone 1: registry, dataset, intake

**Agent registry (hall passes).** YAML manifests in `registry/` for all five agents (intake,
coverage check, critic, risk and fraud, recommendation). Each names an owner, risk tier, status,
model, tool allow-list and the sensitive data classes it may see. The registry refuses agents
with no manifest, agents whose status isn't `active`, and tools the manifest doesn't list. Each
manifest has a SHA-256 digest; the JSON schema is in `registry/agent_manifest.schema.json`, and a
test fails if it drifts.

**Synthetic dataset.** A fictional policy wording (Wayfarer Travel Protection, from fictional
insurer Lantern Ridge Mutual) with numbered clauses and Essentials / Plus plans, policy records,
and claims with full ground truth. Six claims at first; 26 after #8, 34 after #11, 36 after #13.

**Intake agent.** Claude Haiku 5.5 with structured outputs (`IntakeExtraction`). Claim text is
fenced as untrusted data; refusals and truncated output raise errors.

**Tracing.** Langfuse, on only when both keys are set. Usage lives on the Anthropic SDK's own
span (#2 fixed double-counting).

### Milestone 2: pipeline and baseline (#4, #5, #8, #9)

- Coverage check (Sonnet 5.5), risk and fraud (Haiku 5.5, fixed flag vocabulary) and
  recommendation (Sonnet 5.5) made active.
- `agents/base.py`: one call path for every agent (hall-pass check, structured output, refusal
  handling, trace metadata, an `AgentCall` record with version, model, digest, prompt version,
  tokens and time).
- `governance/routing.py`: the routing rule in code.
- `pipeline.py`: intake → coverage → risk → recommendation → route.
- `hall_monitor/evals/`: deterministic scoring with no LLM judge, a hallucination check that every
  value traces to the claim or wording, list-price cost per claim, and a baseline runner.
- Dataset grown to 26 claims (#8) covering every policy rule; clause 1.7 added to define actual
  cash value.

### Milestone 3: critic (#10, #11, #12)

- `agents/critic.py` (Sonnet 5.5): checks intake against the claim, amounts against named limits
  and flags against evidence; sends issues back up to twice; leftover disagreement goes to an
  adjuster.
- Policy lookup gate in `pipeline.py`: one intake retry, then stop and route to an adjuster.
- Coverage label set in code by `CoverageAssessment.from_finding`.
- Review fixes (#11): routing checks facts rather than labels; refusals, API errors, invalid
  output and registry refusals route to a person; fenced text is escaped; critic revisions keep
  before/after; Langfuse decorators no longer capture inputs or outputs; `registry/approvals.yaml`
  pins each manifest digest and prompt hash, and CI fails on an unversioned prompt change.
- Claims 027-034 test caps and limits. Clause 3.1 now says the delay allowance is pooled.
- #12: `incident_location` comes from the narrative only (intake-v3); a code check fills a
  missed policy number when exactly one valid `WTP-ESS/PLS-nnnnnn` match is in the text; a
  seeded-error critic eval (`hall_monitor/evals/critic_seeded.py`).

### Milestone 4: governed MCP tools (#13)

- `hall_monitor/tools/server.py` (fastmcp): `policy_lookup` and `claims_history`, in-process or
  over stdio.
- `hall_monitor/tools/gateway.py`: per-agent allow-lists, `registry.check_tool` on every call,
  and every call (allowed or refused) recorded on `TriageResult.tool_calls` with a result hash.
- Agents fetch their own records through a tool-use loop in `run_agent` (up to 6 rounds).
- New flag `prior_similar_claim`; claims 035 and 036; claim_005's key gains the flag.
- Eval runner made crash-safe (`raw_results.jsonl` saved per run) and API failures counted as
  eval errors, not stopped claims.

### Milestone 5: approval gate (#15)

- `hall_monitor/workflow.py` (LangGraph) with a SQLite checkpointer (`var/checkpoints.sqlite`), one
  thread per claim, so a claim waits for a person across restarts.
- `python -m hall_monitor.review list | show | decide`; the adjuster quotes the evidence-pack
  SHA-256.
- `governance/approval.py` checks the adjuster is registered (`registry/adjusters.yaml`), the
  authority limit, senior-only payment of fraud-flagged claims, reasons for overrides and
  denials, and the evidence hash.
- `python -m hall_monitor.evals.override` simulates the human override rate from a saved run.

### Milestone 6: audit log (#16)

- `hall_monitor/governance/audit.py`: append-only SQLite log (`var/audit.sqlite`), each entry
  hashed over its fields and the previous hash; triggers refuse `UPDATE` and `DELETE`.
- `verify()` names changed, missing or reordered entries; anchoring with `audit head` and
  `verify --expect-seq … --expect-hash …` catches a consistent rewrite.
- No claim text in the log. CLI: `python -m hall_monitor.audit verify | head | show <claim>`.

### Milestone 7: cost and routing (#17)

- Every system prompt sent as a cacheable block in `agents/base.py`.
- `gateway/cost.py`: cache-aware pricing; `TriageResult.cost_usd` on every result; cost by agent
  in the eval report and cost in the audit log.
- Manifests may name `economy_model` and `economy_max_claim_usd`; coverage check and
  recommendation name Haiku 5.5 for claims up to $1,000. `--model-routing`, off by default.

### Milestone 8: privacy and adversarial (#18)

- `gateway/redaction.py`: removes dates of birth, emails, phones, Luhn-valid card numbers, card
  endings, passport and SSN numbers before any model sees the text; only counts are recorded.
- Data classes corrected; the recommender is `[financial]` only and gets a structured summary.
- The gateway refuses lookups for any policy but the claim's own.
- `gateway/injection.py`: deterministic injection signals; any signal routes to a person.
- `evals/adversarial.py` (ten attacks in `data/synthetic/adversarial/cases.json`) and
  `evals/fairness.py` (each claim re-run under six names). Runners built, not yet run live.

### Milestone 9: framework mapping and eval gate (#20)

- `controls/controls.yaml`: 18 controls mapped to NIST AI RMF 1.0 and FINOS AIGF v3, plus 16

- `docs/controls.md` generated; `tests/test_controls.py` fails on missing references, unknown IDs,

- `hall_monitor/evals/gate.py` with thresholds in `evals/gate.yaml`, run on every PR; stale

- `.github/workflows/live-eval.yml`: manual, paid eval run that uploads results and never commits.

## Decisions

- **Routing is a code rule, not a model judgement**, and from #11 it checks facts (amounts, risk,
  next step, critic changes) rather than labels. Every wrong answer in the baselines was still
  routed correctly.
- **The coverage label is computed in code** from the amount, removing the claim_014 error class.
- **No refusal fallback model.** A silent switch to a model the hall pass doesn't name would break
  the registry, so a refusal stops the claim instead.
- **The critic loop is plain Python;** LangGraph came in with the approval gate, where interrupts
  and checkpoints are needed.
- **Keep the critic** as insurance at about $0.015 per claim, based on the seeded-error eval.
- **The adjuster's decision is bound to the evidence-pack hash,** so the record proves what they saw.
- **No claim text in the audit log or in Langfuse,** so personal data doesn't land in stores that
  can't be edited or aren't governed.
- **Audit chain alone can't detect a full rewrite;** the defence is an external anchor, stated
  plainly in the README.
- **Economy model routing ships off** until it's measured: turning it on unmeasured would be the
  silent model change the controls exist to prevent.
- **Narrow redaction patterns** so dates, amounts and policy numbers survive.
- **Stale eval results warn, not fail,** until a fresh baseline exists.
- **Answer-key changes are disclosed** in `data/synthetic/README.md`, including claim_005 (750 →
  490) after the first run showed the key was wrong.
- **Result-citing PRs merge without squashing** so the commits the reports cite stay on `main`
  (#5 fixed the one that was squashed).

## Open questions

- Langfuse's older read API is removed on 2026-11-16. Sending traces is unaffected; any eval
  code that reads traces back must use `/api/public/v2/observations`.
- Does economy routing (Haiku for coverage and recommendation under $1,000) lose accuracy?
- The critic's main target, a live amount slip, didn't occur in 48 cap-test runs; is the seeded
  eval enough evidence, or should it be harder?
- Audit events are written when triage finishes, grouped by kind, so the exact interleaving isn't
  recorded; and a crash between a decision event and the checkpoint save could log a decision
  twice. Both are listed as gaps.
- Adjuster reasons are stored as written in the audit log (listed as a gap).
- The simulated override rate assumes adjusters agree with the answer key; real rates are unknown.
- The fairness eval varies names only, not pronouns.
