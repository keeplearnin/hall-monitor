HALL PASShall-monitor · architecture · after milestone 2 · November 2026

Governance sits in the call path and the router, not inside the model

Four agents run as a single-pass pipeline. Every model call goes through one function that checks the agent's hall pass, calls the model the pass names, validates typed output and records what ran. Routing to a human is a plain code rule. Python 3.12, Claude Haiku 5.5 and Sonnet 5.5, Pydantic, Langfuse.

Every agent call records

agent_id, agent_version
which hall pass ran
manifest_digest
SHA-256 of the exact manifest
model
taken from the pass, never chosen at call time
prompt_version
e.g. coverage-check-v1
input/output_tokens
output includes thinking
seconds
wall time of the call

Design decisions

  • Routing is code, not a model.An injected instruction or a confident model can't skip review. The rule is unit-tested.
  • The pass pins the model. No fallback model.A refusal fails the run loudly. A silent switch would run a model the pass doesn't name.
  • Typed contracts end to end.Each agent returns a Pydantic model via structured outputs; unknown fields are rejected.
  • Customer text is evidence, never instructions.Fenced in tags and named as untrusted in every prompt. Adversarial tests in M8.
  • Deterministic scoring, no LLM judge.Reproducible and nearly free. Hallucination means a value not traceable to the claim or policy.
  • Dependencies arrive with the milestone that needs them.LangGraph with the critic loop and approval interrupts, fastmcp in M4, Postgres in M5–M6.
