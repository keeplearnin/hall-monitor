HALL PASShall-monitor · architecture · after milestone 4 · November 2026

Governance sits in the call path, the tool gateway and the router, not inside the model

Five agents triage a claim. Every model call goes through one function that checks the agent's approved hall pass, calls the model the pass names, runs any tool calls through a gateway that enforces the pass's allow-list, validates typed output and records what ran. A critic checks the work and sends errors back. Routing to a human is a plain code rule that checks facts, not the agents' labels. Python 3.12, Claude Haiku 5.5 and Sonnet 5.5, Pydantic, fastmcp, Langfuse.

Every claim records

each model call
agent, version, model, manifest digest, prompt version and hash, input hash, Anthropic request IDs, tokens, time
each tool call
who called, which tool, arguments, allowed or refused, hash of the result
each critic review
the issues raised, and every revision's before and after
code corrections
e.g. a policy number filled in from the claim text
the route
auto or adjuster, with every reason
a stopped claim
why it stopped, plus everything recorded up to then

Design decisions

  • Routing checks facts, not labels.A $0 payout is a denial whatever the recommendation says; a payout above the claim, any risk above low, or a critic change goes to a person.
  • Approved permits and prompts.approvals.yaml pins each manifest digest and prompt hash. Unapproved versions are refused at run time; CI fails on an unapproved prompt change.
  • Records only through the gateway.The allow-list is enforced on every call, not just declared. The pipeline's own lookup uses the same audited path.
  • Failures go to a person.Refusals, API errors, invalid output and refused hall passes stop the claim with the reason recorded.
  • The critic is insurance.It caught 84 of 84 planted errors with 1 false alarm in 34, for about 1.5¢. Plain Python loop; LangGraph comes with the approval gate.
  • Untrusted text stays fenced; traces stay clean.Claim text and model output are escaped. Langfuse gets IDs, hashes and token counts only.
  • The pass pins the model.No silent fallback to another model on refusal.
