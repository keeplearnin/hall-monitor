HALL PASShall-monitor · architecture · after milestone 10 · November 2026

Governance sits in the call path, the tool gateway, the router and the record, not inside the model

Five agents triage a claim. Every model call goes through one function that checks the agent's approved hall pass, calls the model the pass names, runs any tool calls through a gateway that enforces the pass's allow-list, validates typed output and records what ran. A critic checks the work and sends errors back. Routing to a human is a plain code rule that checks facts, not the agents' labels; claims routed to a person wait at an approval gate, and every step goes into a hash-chained audit log. Python 3.12, Claude Haiku 5.5 and Sonnet 5.5, Pydantic, fastmcp, LangGraph, SQLite, Langfuse.

Every claim records

each model call
agent, version, model and tier, manifest digest, prompt version and hash, input hash, request IDs, tokens incl. cache, cost, time
each tool call
who called, which tool, arguments, allowed or refused (and why), hash of the result
each critic review
the issues raised, and every revision's before and after
code checks
identifiers redacted (counts by type), injection signals, policy-number corrections
the route
auto or adjuster, with every reason
the decision
who decided (a registered adjuster ID), the AI's recommendation, any override and why, the evidence hash
the audit log
all of the above as hash-chained entries; IDs, hashes and decisions only, never claim text

Design decisions

  • Routing checks facts, not labels.A $0 payout is a denial whatever the recommendation says; a payout above the claim, any risk above low, a critic change or a sign of injection goes to a person.
  • Approved permits and prompts.approvals.yaml pins each manifest digest and prompt-template hash. Both are checked at run time and the template hash is recorded on every call; CI fails on an unapproved change.
  • Records only through the gateway, only for this claim.The allow-list and the claim's policy number are enforced on every call; refusals are logged.
  • Minimum data per agent.Identifiers are removed from claim text before any model; the recommender sees a structured summary only, enforced by its input schema. Manifest data classes are declared, not yet enforced.
  • Injection: defence in depth.Claim text is escaped and fenced, a code detector routes suspicious claims to a person, and lookups can't leave the claim's scope.
  • A record that shows tampering.Hash-chained and append-only. Copy the chain head elsewhere: that's what catches a full rewrite.
  • Cheaper models only when measured.Economy routing is approved per manifest but off until evaluated. The critic never economises.
